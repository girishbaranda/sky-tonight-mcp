# v0.5 — Streamable HTTP transport

**Status:** spec
**Date:** 2026-05-01
**Lesson this version teaches:** the *transport* is pluggable. The same `McpServer` and the same eleven `register*()` calls run unchanged behind a second transport. MCP is wire-compatible across stdio and HTTP because the protocol is JSON-RPC 2.0; only the framing changes.

## Goal

Add a Streamable HTTP entry point so the server can run as a long-lived process that any MCP host (or a curl) can talk to over `POST /mcp`. Keep stdio working untouched. No auth, no deploy recipes, no session state — the only concept this version introduces is "the transport is interchangeable."

## Non-goals

- **Authentication.** v0.5 ships no auth. Bind defaults to `127.0.0.1`. Multi-user remote with OAuth 2.1 is v0.6.
- **Deploy artifacts.** No Dockerfile, no `fly.toml`, no Workers adapter. Code + docs only — the user picks a host. Revisited in v0.7 ("Publish") once auth lands.
- **Stateful sessions.** No `Mcp-Session-Id` handling, no SSE channel. Our tools have no notifications, no progress updates, and no streamed responses, so a stateful transport would be ceremony with no payoff.
- **HTTPS termination.** The Node http server speaks plaintext. Production users put it behind nginx / Caddy / a tunnel.
- **Per-user data scoping.** The SQLite log stays a single shared file. With no auth, all clients sharing one process share one log; that is a v0.6 problem.
- **Replacing stdio.** Stdio remains the default tutorial entry point and the binary `claude mcp add` users wire up.

## Architecture

Three changes, one new dependency: zero.

### New: `src/lib/mcp-server.ts` — server factory

Pulls the eleven `register*()` calls out of `src/server.ts` into a pure factory:

```ts
export function createMcpServer(): McpServer {
  const server = new McpServer({ name: "sky-tonight", version: "0.5.0" });
  registerObjectsVisible(server);
  registerIssPasses(server);
  registerMoonPhase(server);
  registerDeepSkyVisible(server);
  registerLogObservation(server);
  registerRecallLog(server);
  registerMessierResources(server);
  registerConstellationResources(server);
  registerPlanTonightSession(server);
  registerIdentifyObject(server);
  registerTourConstellation(server);
  return server;
}
```

This is the only refactor. Both transports call it.

### Trimmed: `src/server.ts` — stdio entry

Shrinks to roughly:

```ts
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import { createMcpServer } from "./lib/mcp-server.js";

const server = createMcpServer();
await server.connect(new StdioServerTransport());
```

The v0.1 tutorial story (`server.ts` shows the entire shape of an MCP server) is preserved; the four-statement skeleton in the README still describes this file accurately, just with `createMcpServer()` standing in for the inline registrations.

### New: `src/http.ts` — HTTP entry

Stateless, fresh `McpServer` + `StreamableHTTPServerTransport` per request. Node's built-in `http` module — no express, no body parser. Two exports: a `startHttpServer({ host, port })` factory that returns the running `http.Server` (used by tests and the smoke script), and a top-level `if` block that calls it when the file is executed directly. Skeleton:

```ts
import http from "node:http";
import { fileURLToPath } from "node:url";
import { StreamableHTTPServerTransport } from "@modelcontextprotocol/sdk/server/streamableHttp.js";
import { createMcpServer } from "./lib/mcp-server.js";

export function startHttpServer({ host, port }: { host: string; port: number }): Promise<http.Server> {
  const httpServer = http.createServer(async (req, res) => {
    if (req.url !== "/mcp") {
      res.writeHead(404).end();
      return;
    }
    if (req.method !== "POST") {
      res.writeHead(405, { Allow: "POST" }).end();
      return;
    }
    const server = createMcpServer();
    const transport = new StreamableHTTPServerTransport({ sessionIdGenerator: undefined });
    res.on("close", () => { transport.close(); server.close(); });
    try {
      await server.connect(transport);
      await transport.handleRequest(req, res);
    } catch (err) {
      console.error("[http] handler error:", err);
      if (!res.headersSent) res.writeHead(500).end();
    }
  });
  return new Promise((resolve) => httpServer.listen(port, host, () => resolve(httpServer)));
}

if (process.argv[1] === fileURLToPath(import.meta.url)) {
  const host = process.env.HOST ?? "127.0.0.1";
  const port = Number(process.env.PORT ?? 3000);
  const server = await startHttpServer({ host, port });
  console.error(`sky-tonight http on http://${host}:${port}/mcp`);
  for (const sig of ["SIGINT", "SIGTERM"] as const) {
    process.on(sig, () => server.close(() => process.exit(0)));
  }
}
```

That's the entire transport. The "fresh server + fresh transport per request" pattern follows the SDK guidance for stateless mode and means concurrent requests cannot see each other's state. The factory makes the test and smoke flows trivial — they pass `port: 0` to get an OS-assigned free port and read it back from `server.address()`.

## Behavior

### Endpoint
- `POST /mcp` — the only valid request.
- `GET /mcp`, `PUT /mcp`, etc. → `405 Method Not Allowed`, `Allow: POST` header, empty body.
- Any other path → `404 Not Found`, empty body.
- No `GET /mcp` SSE channel — stateless mode has nothing to subscribe to.
- No `/health` route in v0.5.

### Config (env vars)
- `PORT` — default `3000`.
- `HOST` — default `127.0.0.1`. The README documents `HOST=0.0.0.0` for remote use with an explicit warning that v0.5 ships no auth.
- `SKY_TONIGHT_DB` — unchanged from v0.4.

No CLI flags; env vars only.

### Logging
- All diagnostics go to `console.error` (stderr), matching `src/server.ts`. Stdout-safety is no longer required for HTTP, but keeping the rule means logs pipe identically across both transports.
- One startup line: `sky-tonight http on http://127.0.0.1:3000/mcp`.
- No per-request access log. v0.6 will reshape what's worth logging once auth introduces a user dimension.

### Errors
- Bad method → `405`. Bad path → `404`. Both with no body.
- Malformed JSON, unknown tool, schema-violating arguments → handled by the SDK's `transport.handleRequest()` and returned as JSON-RPC error envelopes, just like over stdio.
- Top-level `try/catch` around `transport.handleRequest()` so a thrown handler returns `500` (if headers not yet sent) instead of crashing the process.

### Concurrency
- Each request gets its own `McpServer` instance and its own transport, so two concurrent `tools/call` invocations have isolated handler state.
- `better-sqlite3` serializes writes inside a single process, so the shared observation log is safe under concurrent `log_observation` calls.

### Shutdown
- `SIGINT` / `SIGTERM` → `httpServer.close()` (drains in-flight, refuses new) → `process.exit(0)`.
- Per-request `server.close()` runs on the response's `close` event (already wired in the snippet above).
- No graceful drain timeout. Personal tool; Node's defaults are fine.

## Tests

New file: `src/http.test.ts`. Uses the existing `tsx --test` runner; no new test deps. Sets `SKY_TONIGHT_DB=":memory:"` so it doesn't touch disk. Spins up the HTTP server on port `0` (OS-assigned) and drives it with built-in `fetch`.

Cases:
1. `initialize` round-trip — `POST /mcp` returns `200`, response body echoes `protocolVersion`, advertises `serverInfo.name === "sky-tonight"`.
2. `tools/call moon_phase` — returns `200` with non-empty content array.
3. `GET /mcp` → `405` with `Allow: POST` header.
4. `POST /nope` → `404`.
5. Concurrency smoke — two concurrent `moon_phase` calls via `Promise.all`, both succeed.

Each case spins up + tears down its own server in `before`/`after` hooks, mirroring `observation-log.test.ts`.

## Smoke script

`scripts/smoke-test.ts` already exercises the libs directly. Add a closing section that:
