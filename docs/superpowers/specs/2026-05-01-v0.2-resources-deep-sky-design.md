# v0.2 — Resources + Deep-Sky Visibility — Design

**Date:** 2026-05-01
**Status:** Approved (pending spec review)
**Roadmap step:** v0.2 in [README.md](../../../README.md)

## Goals

Add the MCP **Resources** primitive to sky-tonight by exposing two object catalogs (Messier and IAU constellations), and add a tool that uses the Messier catalog to compute deep-sky visibility from an observer location.

v0.1 demonstrated **Tools**. v0.2 demonstrates **Resources** and shows how Tools and Resources compose inside one server: the resources are the LLM's read-only catalog; the new tool is what turns that catalog into "what can I actually see tonight?"

## Non-goals

- **Constellation visibility tool.** Constellations are sky regions, not point sources. The `best_months` field on each constellation entry is the visibility hint.
- **NGC / Caldwell / IC catalogs.** Messier alone gives 110 well-curated targets; adding more dilutes the lesson and bloats the JSON.
- **Network fetch at runtime for catalog data.** Catalogs are static (Messier hasn't changed since 1781); JSON files are committed and treated as constants.
- **Streamable HTTP transport** (v0.5), **Prompts** (v0.3), **persistent observation log** (v0.4).

## Resources

All resources advertise `mimeType: "application/json"`.

### Catalog index resources (fixed URIs)

Two fixed-URI resources, one per catalog. These are returned by `resources/list`.

`sky://catalog/messier` — JSON array of compact entries:

```json
[
  {
    "id": "M1",
    "name": "Crab Nebula",
    "type": "supernova_remnant",
    "magnitude": 8.4,
    "constellation": "Taurus",
    "uri": "sky://messier/m1"
  },
  ...
]
```

`sky://catalog/constellations` — JSON array of compact entries:

```json
[
  {
    "name": "Orion",
    "abbreviation": "Ori",
    "hemisphere": "equatorial",
    "brightest_star": "Rigel",
    "uri": "sky://constellation/ori"
  },
  ...
]
```

The `uri` field on each index entry tells the LLM how to drill into a specific object — making per-object resources discoverable without enumerating all 198 in `resources/list`.

### Per-object resources (URI templates)

Two URI templates, registered via `ResourceTemplate`. These are returned by `resources/templates/list`. We do **not** provide a list callback that expands the templates into 198 concrete entries — the LLM navigates via the index resources instead. This keeps `resources/list` small and matches the "browse → drill in" mental model.

- `sky://messier/{id}` — `{id}` is case-insensitive (`m31` and `M31` both resolve)
- `sky://constellation/{abbr}` — `{abbr}` is the IAU 3-letter abbreviation, case-insensitive

### Per-object data shapes

**Messier object** (J2000 coordinates — required for astronomy-engine):

```json
{
  "id": "M31",
  "name": "Andromeda Galaxy",
  "type": "spiral_galaxy",
  "constellation": "Andromeda",
  "ra_deg": 10.6847,
  "dec_deg": 41.2687,
  "magnitude": 3.4,
  "size_arcmin": 178,
  "best_months": ["Sep", "Oct", "Nov", "Dec"],
  "description": "Closest large spiral galaxy at 2.5M light-years..."
}
```

`type` is one of: `galaxy`, `spiral_galaxy`, `elliptical_galaxy`, `nebula`, `planetary_nebula`, `supernova_remnant`, `open_cluster`, `globular_cluster`, `double_star`, `asterism`.

**Constellation:**

```json
{
  "name": "Orion",
  "latin_genitive": "Orionis",
  "abbreviation": "Ori",
  "hemisphere": "northern" | "southern" | "equatorial",
  "best_months": ["Dec", "Jan", "Feb", "Mar"],
  "brightest_star": { "name": "Rigel", "magnitude": 0.13 },
  "notable_objects": ["M42 (Orion Nebula)", "M43"],
  "story": "The Hunter, with belt of three stars..."
}
```

## Tool: `deep_sky_visible_tonight`

A new tool, separate from `objects_visible_tonight`. The two tools share output shape but differ in inputs and audience.

### Inputs

| Field | Type | Required | Default | Notes |
|---|---|---|---|---|
| `latitude` | number, -90..90 | yes | — | |
| `longitude` | number, -180..180 | yes | — | |
| `date` | ISO string | no | tonight | Anchors the night window |
| `min_altitude_deg` | number, 0..90 | no | **30** | Higher than naked-eye default; deep-sky needs height to escape light pollution |
| `max_magnitude` | number | no | **9** | Small-telescope reach; 6 ≈ naked eye, 12 ≈ serious scope |
| `type_filter` | enum | no | none | One of `galaxy` / `nebula` / `cluster`. See mapping below. |

### Behavior

1. Compute the night window for the date (sunset → sunrise) using `findNightWindow` from `lib/astronomy.ts`.
2. Load the Messier catalog from `src/data/messier.json` via `catalog.ts` (direct filesystem read, **not** through the MCP resource layer — see "Internal data access" below).
3. Filter: `magnitude <= max_magnitude` AND (if `type_filter` is set) the object's `type` falls within the filter's category. Mapping:
   - `galaxy` filter → matches `galaxy`, `spiral_galaxy`, `elliptical_galaxy`
   - `nebula` filter → matches `nebula`, `planetary_nebula`, `supernova_remnant`
   - `cluster` filter → matches `open_cluster`, `globular_cluster`

   `double_star` and `asterism` are not selectable via filter — they're always included when no filter is set.
4. For each surviving object, sample alt/az every 15 minutes through the night window using astronomy-engine. Convert J2000 RA/Dec to topocentric alt/az.
5. Keep objects whose peak altitude ≥ `min_altitude_deg`.
6. Sort by peak altitude descending, cap at top 20.

### Output

Plain text, multi-line. First line is the night window summary (matching `objects_visible_tonight`'s opening line), then a blank line, then a header like `Visible deep-sky objects (N matched, ranked by peak altitude):`, then one indented line per object:

```
Night window (UTC): 2026-05-01T13:37:01Z → 2026-05-02T00:35:41Z (11.0 hours of darkness)

Visible deep-sky objects (12 matched, ranked by peak altitude):
  M31 (Andromeda Galaxy): peaks 67.3° in S at 2026-05-01T19:42:00Z, mag 3.4 [spiral_galaxy in Andromeda]
  M42 (Orion Nebula): peaks 54.1° in W at 2026-05-01T13:55:00Z, mag 4.0 [nebula in Orion]
  ...
```

If filters produce zero matches: a single line `No deep-sky objects matched your filters tonight.`

### Error handling

- Polar day / polar night → `isError: true` with explanation, mirroring the existing tool.
- Empty result set after filtering → normal response (not an error) with "No deep-sky objects matched your filters tonight."

### Resource error handling

Per-object resource reads for unknown IDs (e.g. `sky://messier/m999` or `sky://constellation/zzz`) return a JSON-RPC error per the MCP spec — the SDK surfaces this as a thrown error in the read callback, which translates to a structured client-side error. The implementation should `throw new Error("Unknown Messier object: m999")` rather than returning malformed content.

## Internal data access vs. Resource layer

The new tool reads `src/data/messier.json` directly via `catalog.ts`, not through the MCP resource read path. **This is intentional and worth a code comment.** Resources are a client-facing interface; a tool inside the same server using its own data files is a separate concern. Routing the tool's data access through the resource layer would conflate the two and add no value.

`src/lib/catalog.ts` exports:
- `loadMessier(): MessierObject[]`
- `loadConstellations(): Constellation[]`
- `findMessier(id: string): MessierObject | null`
- `findConstellation(abbr: string): Constellation | null`
- `filterMessier(objects, predicate): MessierObject[]`

These are imported by both the resource registrants (`src/resources/*.ts`) and the new tool (`src/tools/deep-sky-visible.ts`).

## Authoring the data

The Messier catalog (1781) and IAU constellation list (1930) are static, well-known, public-domain references. The JSON files are authored directly in this project, sourced from training data with spot-checks against external references for the famous entries.

**Spot-check entries** (must match published references):

| Entry | Field | Expected |
|---|---|---|
| M31 | magnitude, constellation | 3.4 ± 0.1, Andromeda |
| M42 | name, type | Orion Nebula, nebula |
| M45 | name, type | Pleiades, open_cluster |
| M51 | name | Whirlpool Galaxy |
| M104 | name | Sombrero Galaxy |
| Orion | brightest_star.name, hemisphere | Rigel, equatorial |
| Cassiopeia | hemisphere | northern |
| Crux | hemisphere | southern |
| Ursa Major | abbreviation | UMa |

No fetch script. The data files are committed once.

## Testing

Extend `scripts/smoke-test.ts` with:

1. **Catalog integrity:** assert `messier.json` has exactly 110 entries, every `id` matches `/^M\d+$/`, every `magnitude` is a finite number. Assert `constellations.json` has exactly 88 entries, every `abbreviation` is a 3-letter string.
2. **Spot checks:** verify the table above (M31 mag 3.4, M42 named "Orion Nebula", etc.)
3. **Tool exercise:** call `deep_sky_visible_tonight` for Gandhinagar (23.2156, 72.6369) tonight at default parameters; assert ≥1 object returned and that the prose output matches the expected format.
4. **JSON-RPC drive:** send `resources/list` (expect 2 fixed-URI entries), `resources/templates/list` (expect 2 templates), `resources/read sky://catalog/messier` (expect JSON array of 110), `resources/read sky://messier/m31` (expect M31 JSON).

The existing v0.1 tests (moon, planets, ISS, JSON-RPC handshake) stay unchanged and must continue to pass.
